# 跨项目团队工作流

## 任务上下文

当前用户指示、适用 AGENTS、已确认目标及路线优先；只加载本任务相关文档。主聊天承担小策，显式委派时只保留一位制作人负责产品调度与 STATE；领域协调者不取代制作人。维护角色、技能或看板不自动启动游戏生产。

派工携带 `team_context`：实际 `skill_root`、`project_root`、`repo_root`/`harness_root`、AGENTS 与 STATE/路线入口及当前目标摘要、引擎/版本/平台、任务范围与验收条件、相关规则章节、看板是否接入。无 Git、未知阶段或缺入口如实标注。接收者显式读适用 AGENTS，并核对 STATE 的当前目标；任务包充分且未冲突时复用其中的项目、阶段、样板与预算，只回查缺项或受影响的相关原文，不重建全项目上下文。恢复、过期或目标冲突时重新核对相关状态与证据；阶段权威在项目文档，不在数据库。

`skill_root` 内 `references/` 为共享规则、`roles/` 为完整角色、`scripts/review_gate.py` 为保留的历史票门（当前三人门暂停）。独立调用无上下文时，从 `CODEX_HOME/skills/game-team`，未设置则用户 home 下 `.codex/skills/game-team` 定位，再从当前目录或用户目标确认项目与 Git 根；缺资源如实说明，不猜旧盘符。只读当前项目明确引用且本任务适用的章程；不扫描其他项目，不继承其阶段、技术栈、发布授权、凭证或看板接入。

每次启动/恢复的首条简短进度和最终交接用角色固定名字与岗位署名；同岗位并行加实际模块/任务短名。交接给实际 task_id 和已有 run_id，未提供不编造。昵称不替代 TOML name、真实 role/instance、run/parent 或票据身份，不杜撰真人履历或声称改变原生卡片/看板显示。

阅读范围：小策、小岳读本篇全篇；小墨另读美术工作流全篇。策划读“任务包与写入边界”及 [DESIGN_WORKFLOW.md](DESIGN_WORKFLOW.md)，小策派设计任务时也读；开发另读“派工与集成”，美术专家/小墨另读“任务包与写入边界”，验收另读“验收与完成”；美术按 [ART_WORKFLOW.md](ART_WORKFLOW.md) 的分节指引读取。只有已接入看板才读其适配并执行上报。

## 派工与集成

### 任务包与写入边界

新生产任务默认用干净上下文，工具支持时设 `fork_turns="none"`，传完整岗位指令和必要任务包，不默认继承父聊天。相同任务可复用原实例，只补变化；新独立评审与复审仍用新干净实例。十生产岗位的命名角色不可用时加载本包对应 TOML 的完整指令并如实记录；已禁用三位不得按此方式回退，不以显示名冒充角色。按剩余容量分批，交接后释放无任务实例，不常驻全岗。

任务包交代实际 task_id、目标/边界、可观察出口、接口/依赖、唯一文件所有权、相关入口和未测项；Git任务另给真实基线 SHA、目标分支、独立分支/worktree 路径。美术单件补充其 [任务规格](ART_WORKFLOW.md#单件制作)。共享场景、Prefab、配置、图集和元数据各有唯一写入者；不回退他人修改，跨范围先协调。

同一切片由唯一小岳统筹代码和正式资产集成，小程不另建开发团队，小墨不充当第二技术负责人。即使只有一个实现者也须隔离与独立审查。有 Git 时在独立任务 worktree/分支实现，不在共享主区切换或覆盖文件；依赖任务从前置已集成的真实基线开始。远端、默认/目标分支与授权按实际确定，不假定 main/origin，实现者不自行合入，不直接写推默认分支、不 force push。

有远端/PR能力且获授权时，检查后 commit、push 任务分支并开指向实际目标的 PR，按客户端要求附加到当前任务；无此能力仍保留本地 diff/提交及独立审查，不虚构 PR。无 Git 则用独立输出目录、清单与内容摘要，不擅建远端或初始化第二仓库。既有脏内容作为隔离基线时，仅集成本轮经审增量，不把旧工作混入发布。

### 技术审查与合入

小岳逐最新 HEAD 核对实际 diff、范围、接口、引用/元数据及必要检查，留存所审 SHA 和结论后才合入同一 SHA；更新后重审。实质问题退原实现者在原分支/PR返修，不绕过保护；共用 GitHub 身份只用评论型 review，不冒称独立账号 Approve。自己实现的内容交另一实例审查。集成新代码继续走修复任务，不重复实现已委派模块。

交付实际版本、差异、入口、检查证据与未测项；含未提交内容时另锁实际内容/构建摘要，不能仅用 HEAD。实现者交付待小岳审查，小岳集成交付待制作人安排验收。交付证据已保留、增量已集成且 worktree 干净才清理，不能强删未交接修改。按影响验证，不为提示词措辞写测试。

## 验收与完成

小策沿用当前范围，先验证最小完整循环，再处理最影响理解、选择和节奏的 1—3 个问题；玩法验证可占位，美术切片需真实接入。普通打磨目标 1—2 轮收敛，仍有严重问题就修复或缩小切片，不为轮数放行。design-review/play-review 为小谨的独立建议，由小策取舍，不算验收。

小谨 acceptance 独立核对明确集成版本和承诺，不验自己实现的结果；失败回派技术线修复，再验新候选。程序检查、Agent操作/观看、真人反馈、平台与目标设备分别陈述，缺证保留待验。生成成功、自查、小墨专业复核、submitted、合入均不等于产品通过。

小策拟宣告游戏任务、切片、阶段或版本完成（含带遗留通过），须满足小谨独立验收及适用前置、真人和平台门，保留明确版本、实际证据和未测项。[三人完成门](COMPLETION_REVIEW.md)按 2026-10-25 用户要求暂停：小川、小禾、小砚已禁用，不调用、不用普通 agent 或复制指令回退、不收集新票、不把暂停当评审通过；小衡保留但暂停主持。恢复须用户明确要求并先同步角色安装及规则。配置检查不冒称游戏验收。

## 可选看板

默认本地协作；当前项目明确配置/授权接入时才在任务包提供实际 reporter_root、项目/阶段、已有来源 run 和允许事件。未接入不造 run/parent、不调 begin/上报、不索取凭证。接入后使用该项目的真实身份、阶段和事件语义，不假定别的看板也有同样字段、父链或传输实现。

只报重要产物、决策、阻塞及解除、交付和结束，不逐工具轮询；小衡/三评审不上报。凭证、运行数据、对话与思考不入源码或公开包。

使用 AgentBoard v1 适配时：parent 仅表示来源/阶段继承，不代表职级；新执行 lead=true 仅 game-tech-lead，策划与美术协调者均为 false。两策划来源父执行为制作人；策划、开发、技术负责人及四美术的 submitted 均为待审/待接入；正式 verification/verdict 只属独立 game-verifier 的 acceptance，验收来源仅制作人。传输先落本地 outbox 再有界发送，准确确认，失败保留，不阻断开发或伪称 sent；具体调用与允许父链读取当前 reporter_root 的项目适配。
