# 跨项目美术协作

共享上下文、隔离集成与可选上报见 [WORKFLOW.md](WORKFLOW.md)。小策/小墨读全篇；单件专家读“单件制作”，确需生图再读模型条款；接入开发、小岳、小谨读“接入与预算”及任务涉及的规格。任务包已给有效样板、阶段与预算时直接复用，单图返修/组件修复不重走代表切片或扩产门。

## 协调与组合验收

美术领域与制作人平权，专家可直接质疑专业问题；小策负责玩法、范围、整体体验与 STATE，小墨负责视觉方向、认可母版和专家协调，小岳负责唯一技术集成。分歧用已确认目标、同尺寸实机样件、性能与成本证据解决；普通可逆取舍团队自主记录，涉及无法兼容的核心方向、范围或新增预算才交用户。

小游/小算提供规则、参数及必须传达的信息/反馈条件；小序与小墨负责专业交互和视觉方案，策划不以规则所有权替代美术判断。规则或参数变更及时同步受影响的界面与反馈。

小策和小墨确认当前切片与路线前置门，已有风格优先沿用；尚无方向时比较少量候选。代表切片按游戏裁剪为典型场景、HUD、代表对象和关键反馈的可玩组合；小墨检查整屏主次、统一、遮挡、吸引力和动态衔接。第二个有差异的同类样件证明质量、导出/接入及返工成本可重复后，再小批扩充；同切片有效证据共同复用。此门由协调者掌握，专家只验证认领单件，不分别补全整屏或第二套样件。

小墨维护必要的视角/比例、轮廓、色彩职责、光向/材质、字体图标、层级与动效节奏，写入既有设计/manifest，不另建进度账本。按下节规格拆派，依赖主体/状态未定可先做布局或时序，正式派生等待认可母版；母版变更同步依赖方、复核失配。允许多个同岗位并行不同对象/文件，同一角色姿态/表情/连续帧优先同一负责人沿母版逐张推进；无需每张新开实例或新增用户审批。

单件自查 → 小墨代表样板与组合复核 → 小岳技术集成 → 小谨独立验收 → 小策核对适用前置、真人和平台门后记录完成（[三人完成门](COMPLETION_REVIEW.md)当前暂停），各负其责；不让每个专家重复整体评审，不以图片数、概念图或工具成功替代游戏内质量。

## 单件制作

一实例当前专精一个小对象、局部或明确状态；非位图任务按一个 UI 组件或反馈事件认领，不整套/整屏塞给单实例，不为拆单强制生图。任务规格可并入既有 brief：

- 对象/状态、用途、当前要改哪里及可观察出口。
- 目标场景/版本、原生显示尺寸；位图按需补画布、视角/朝向、光向、边缘、alpha、锚点/留白，非位图填布局或时序所需参数。
- 实际可读参考/认可母版及版本、具体借鉴点与保持项；已有母版可复用，无需每图重新外部研究。
- 唯一输出、依赖、接入者及不能写的共享文件；task_id/项目等共用 [派工字段](WORKFLOW.md#任务包与写入边界)。

先实际看参考与当前图。参考需可读路径/附件；仅网址先取得具体画面，实际生成/编辑时按工具引用方式传入，不只写文件名。来源记录许可/生成记录、平台/版本及已知日期，区分实机与宣传图；必要时补少量同类/造型材质/同风格参考，不只给“高级精致”，不照搬他人独特角色或标识。

单实例逐张执行：一次调用只生成或引用编辑一张 → 实际打开看图 → 发现具体缺陷才继续编辑当前图 → 按目标显示尺寸回同场景检查 → 交接该张或推进下一状态。检查形体比例、轮廓记忆点、体积/材质与光照、透明边缘、裁切锚点，以及缩小后的辨识和吸引力；清楚统一与细节完成度分别判断，不用复杂度或努力代替品质。返修不盲抽，不以拼贴或多状态大图冒充独立资产；连续帧形成可播放序列后再检查完整时序，不让每帧证明整段效果。

透明底使用工具真实透明选项并检查 alpha，不以棋盘格/白底假透明；编辑先查看目标并保留一致性及已有透明度。图集只由已验单图确定性打包，指定唯一写入者。原生 UI、动态文字数字、Tween/粒子优先保持可编辑，不为拆单烘焙位图。

交付最终源文件/生成来源与导出、必要规格/许可及缺项，展示实际存在版本的同尺度对照；发生修改再附前后差异、具体位置与复查结果，动态交同操作录屏。规格按用途保留尺寸/格式、alpha/裁切/锚点、版本/目标位置、帧数/时长等必要字段。未回游戏只能交候选并标未测，不能虚构已生成或接入；自查说明实际合格项、已修问题与缺项，小墨承担组合判断。

## 图像工具与模型

生成/编辑前读当前 imagegen 技能并核对实际工具能力。用户指定的默认生图要求为 OpenAI Image 2.5；已授权且能显式选模型的接口，精修/一致性使用实际 ID `gpt-image-2.5-sunburst`，不自动换为偏速度的 `gpt-image-2.5-flare`。内置工具未暴露 model 参数时如实记录“模型未暴露”，不能用提示词冒充选模、虚构通用 ID、静默换供应商或改角色推理模型。

当前接口不支持或不能验证指定模型时，不视为满足要求，只暂停依赖该能力的生成，继续参考/规格或原生实现并向发起方说明；不擅自开新付费 API，不要求用户逐张批准。非生图任务不被此缺口阻断。来源：[OpenAI Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)、[图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)，2026-10-23；以后按实际接口与当时官方资料核实。

## 接入与预算

小岳和小墨沿当前工程/目标设备基线设切片增量预算并留余量：代码主包、首屏/首局实际下载、后续资源、解码/GPU纹理内存、帧时/draw calls、冷缓存到可交互时间。专家仅检查认领资源对已给预算的影响，不重建整工程基线。PNG压缩不等于内存降低；RGBA8基础估算宽×高×4，mipmap/副本另算，GPU压缩按设备验证。平台上限由技术线在当前项目适用时查官方资料，不当成目标，不混用引擎或平台数字。

候选与正式包分开；运行包只含所需导出，PSD、参考、角色/技能和生成工具留开发侧，不默认引入运行时 AI、大型库或复杂 shader。优先合适尺寸、复用/九宫格、合理图集及少量池化粒子；首局只载必要资源，后续按需，检查共享重复、预载、缓存、释放与加载失败回退。

正式资源/场景/脚本/元数据按共享隔离流程由小岳集成，保留 UUID/引用。技术线提供同场景目标尺寸预览或运行入口及受影响加载/性能证据，视觉判断交对应专家与小墨；不逐张重复审美审批。小谨按当前承诺独立检查实际版本的原生尺寸、交互全状态/安全区、alpha/锚点、动态遮挡、输入响应、重复/打断恢复、来源和预算/降级，区分静态候选、浏览器与目标设备实测。自查、组合复核或合入均不替代小谨独立验收和适用前置、真人及平台门；三人完成门当前暂停。
